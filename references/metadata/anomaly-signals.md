# Investigating Metadata Anomaly Signals

Anomaly signals are irregularities, inconsistencies, or unusual artifacts found within a file's metadata, filesystem footprint, or container structure. An operator needs to identify these signals to flag evidence for deeper technical review, determining whether the file represents an original, untampered record or a derived, edited, or synthetic construction.

## Why it matters

Metadata rarely tells a straightforward story. Hardware clocks drift, software encodes files idiosyncratically, and standard workflows routinely strip or alter tags. Recognizing anomalies is not about finding immediate proof of forgery; it is about knowing which technical inconsistencies warrant further questions and require corroboration from independent sources.

## Tools

| Tool | Platform | Notes |
| --- | --- | --- |
| `exiftool` | both | For deep tag and history inspection. |
| `mediainfo` | both | For container and codec consistency. |
| `stat` | both | For filesystem timestamps (flags differ between macOS/Linux). |

## Practical recipes (What to look for)

### GPS presence or absence

*   **Signal:** An image taken with a modern smartphone lacks GPS coordinates, or conversely, a photo supposedly taken with a basic point-and-shoot camera contains high-precision location data.
*   **Command:** 
    ```bash
    exiftool -a -gps:all /path/to/evidence.jpg
    ```

### Timestamp inconsistency

*   **Signal:** The EXIF `DateTimeOriginal`, the container creation date, and the filesystem modification time disagree. For instance, the EXIF indicates capture in 2020, but the filesystem and container headers suggest 2026.
*   **Command:** 
    ```bash
    exiftool -time:all -s /path/to/evidence.mp4
    stat -f '%m %z' /path/to/evidence.mp4   # macOS
    stat -c '%Y %s' /path/to/evidence.mp4   # Linux
    ```

### Editing-software markers

*   **Signal:** Fields like `Software`, `ProcessingSoftware`, or the XMP document history contain names of editing suites (e.g., Adobe Photoshop, Premiere) or operating system save dialogues, rather than the original camera firmware.
*   **Command:** 
    ```bash
    exiftool -Software -ProcessingSoftware -XMP:History -a /path/to/evidence.jpg
    ```

### Thumbnail vs. image mismatch

*   **Signal:** The embedded EXIF thumbnail visually differs from the primary high-resolution image, indicating the main image was edited but the metadata thumbnail was not updated by the software.
*   **Command:** 
    ```bash
    exiftool -b -ThumbnailImage /path/to/evidence.jpg > thumb.jpg
    ```

### Container and codec mismatch

*   **Signal:** The alleged recording device (e.g., an older dashcam) is known to produce `.avi` files with Motion JPEG, but the evidence file is an `.mp4` containing HEVC (`h265`) video.
*   **Command:** 
    ```bash
    mediainfo --Inform="General;%Format%" /path/to/evidence.mp4
    ```

### Re-encode indicators and missing maker notes

*   **Signal:** A video file possesses a low bitrate for its claimed source, or an image is missing the proprietary "Maker Notes" block, serial number fields, or other unique vendor tags normally embedded by Canon, Nikon, or Apple devices.
*   **Command:** 
    ```bash
    exiftool -MakerNotes:all -SerialNumber -InternalSerialNumber -a /path/to/evidence.jpg
    ```

## Pitfalls and Benign Explanations

**CRITICAL RULE:** Every item above must be framed as a signal warranting further investigation, NEVER as proof of tampering. 

Benign explanations exist for all of these anomalies. 
*   Users routinely disable GPS for privacy or battery life.
*   Filesystem timestamps reflect when a file was downloaded, copied, or restored from backup, not when it was created.
*   Social media platforms and messaging apps universally re-encode media, strip Maker Notes, alter codecs, and crush bitrates during transmission to save bandwidth.
*   Merely rotating an image in a default OS viewer might inject editing software markers and update the container date while leaving the thumbnail untouched.
*   Serial number fields may be absent depending on the specific firmware version of the device, even within the same product line.

## Advanced Operational Scenarios

### The "Too Perfect" Anomaly
While missing data is a common anomaly, structured data can be equally suspicious. If a suspect provides a photo claiming to be from five years ago, and the EXIF data contains every single optional tag formatted according to the latest 2026 specifications, the metadata is likely forged. Natural metadata generated by consumer devices is often slightly messy, containing undocumented fields or minor offset errors. Perfect compliance often indicates the use of an automated metadata injection script.

### Temporal Discrepancy Matrix
Advanced operators construct a temporal matrix for critical files, mapping the filesystem `ctime`, `mtime`, and `atime` against the embedded EXIF `CreateDate` and the internal container timestamps. If a video file's internal stream indicates it was encoded hours *after* the filesystem claims it was last modified, this physical impossibility proves that either the system clock was manipulated during acquisition or the file's internal structure has been deliberately tampered with.
