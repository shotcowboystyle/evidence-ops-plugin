# Photo and Video Provenance

This document details methods for establishing the origin, authenticity, and strict chain of custody of photographic and video evidence. Operators consult this when assessing whether a media file is a raw original, when capturing original media in the field, or when relying on emerging cryptographic provenance standards like C2PA to verify the history of a digital asset.

## Why it matters

Metadata blocks like EXIF are trivially editable and inherently do not guarantee a file's authenticity. True provenance relies on cryptographic signatures generated at the point of capture, or on rigorous chain-of-custody practices established immediately upon acquisition. Without these controls, distinguishing maliciously manipulated synthetic media from authentic recordings becomes significantly more difficult, undermining the reliability of the evidence.

## Tools

| Tool | Platform | Notes |
| --- | --- | --- |
| `exiftool` | both | Essential for deep metadata inspection, extraction, and demonstrating fragility |
| `mediainfo` | both | Analyzes structural and container-level metadata for video and audio |
| ProofMode | Android/iOS | Appends cryptographically signed hardware sensor data directly to media captures |
| `c2patool` | both | CLI for validating Content Credentials (C2PA) manifests and provenance chains |

## The illusion of EXIF authenticity

A common misconception in digital forensics is that EXIF data acts as a reliable fingerprint. In reality, EXIF tags are arbitrary strings stored in the file header. An adversary can easily strip all metadata or selectively forge timestamps, GPS coordinates, and camera models. Therefore, the presence of EXIF data is merely a starting point for investigation, not cryptographic proof of origin. True cryptographic provenance (such as C2PA) binds the image data to a signature generated by the device hardware itself.

## Deep provenance markers

When EXIF data is contested or missing, operators must look for deeper physical and structural markers:
- **Photo Response Non-Uniformity (PRNU):** Every digital camera sensor possesses microscopic manufacturing imperfections that create a unique noise pattern in every photo it takes. PRNU acts as a physical ballistic fingerprint for digital cameras, allowing analysts to tie a specific photo to a specific hardware device, independent of EXIF data.
- **Quantization Tables:** JPEG compression relies on quantization tables (DQT). Different camera manufacturers and software editing tools utilize distinct DQT configurations. Analyzing these tables can reveal whether an image was produced directly by an iPhone camera app versus exported from Adobe Photoshop.

## Social Media compression

Operators must understand the destructive nature of social media platforms on digital evidence. When a photo is uploaded to platforms like Twitter, Facebook, or WhatsApp, the backend infrastructure compresses and re-encodes the file.
- EXIF, IPTC, and XMP metadata blocks are almost stripped for privacy and file-size reasons.
- Cryptographic provenance manifests (like C2PA) are routinely destroyed by the re-encoding process.
- The original file hash is irrecoverably altered. 
Acquiring media from these platforms implies acquiring a heavily degraded derivative, not an original.

## Practical recipes

The following commands demonstrate how to inspect metadata, prove its fragility, and validate modern cryptographic provenance standards.

```bash
# 1. Inspect all EXIF and structural metadata using exiftool
# -a keeps duplicate tags, -G1 groups tags by their internal location
exiftool -a -G1 -s "evidence/originals/photo.jpg" > "logs/photo-metadata.txt"

# 2. Analyze video container formats and stream properties with mediainfo
mediainfo --Output=JSON "evidence/originals/video.mp4" > "logs/video-metadata.json"

# 3. Demonstrate how EXIF can be trivially wiped (never run on originals!)
# This rewrites the file, removing all non-essential metadata blocks
exiftool -all= "evidence/derived/scrubbed-photo.jpg"

# 4. Validate a C2PA (Content Credentials) manifest using c2patool
# This checks for cryptographically signed edits and origin data
c2patool "evidence/originals/signed-photo.jpg" > "logs/c2pa-manifest.json"

# 5. Baseline the file with a hash immediately on macOS
shasum -a 256 "evidence/originals/photo.jpg" > "manifests/photo.sha256"
```

## Pitfalls

- **Trusting Unsigned Metadata:** Assuming EXIF data is absolute proof of origin. Any operator can rewrite tags like `DateTimeOriginal` or `GPSLatitude` using `exiftool` in seconds. Treat EXIF as a claim, not a fact.
- **Confusing Attestation with Capture Provenance:** Hashing an image file and timestamping it proves the file existed *in your possession* at a specific time (after-the-fact attestation). It does not prove the file was authentically captured by a camera at that moment. Hardware-signed capture (like ProofMode) is required to prove actual origin.
- **Ignoring Device Context:** Failing to record the capture device's physical state, make, model, and operational environment when taking original photos for an investigation.
- **Relying on Social Media Copies:** Using social media copies as primary evidence is dangerous. Platforms routinely strip EXIF and C2PA metadata, compress aggressive, and re-encode media, destroying any latent provenance signatures.
